# FamilySearch: необязательная загрузка полных индексированных записей

Читайте, если выбран скриптовый сбор большого объёма индексов. Обычный браузерный маршрут из `familysearch-indexes.md` остаётся доступен без настройки этого помощника. `scripts/familysearch_api.py` переносит поисковый цикл исходного помощника: местность → книги → ID записей по кадрам → полные ответы записей → локальный поиск. Дерево не читает и не меняет.

## Выбор и авторизация

Использовать только при явном выборе скриптового маршрута или уже настроенной для него сессии. Не предлагать экспорт cookie как условие обычного исследования. Если отдельной сессии нет, продолжать через встроенный браузер. Не переключаться на скрипт автоматически при блокировке сайта.

Помощник использует внутренние JSON-интерфейсы FamilySearch, а не гарантированный публичный API. Пользователь может самостоятельно предоставить действующее значение `fssessionid` через переменную окружения `FS_TOKEN` или приватный файл `--token-file /private/path/session.txt`. Агент не извлекает cookie из браузера и не просит вставлять секрет в чат. Файл хранится вне навыка и исследовательского дела, с доступом только владельцу. Допускаются само значение или одна пара `fssessionid=VALUE`; весь заголовок Cookie и набор cookies не подходят. Передавать значение аргументом команды не предусмотрено. Уже открытая браузерная сессия не передаётся Python автоматически.

### Где получить сессию

Пользователь выполняет это самостоятельно в браузере, где уже вошёл в FamilySearch:

1. Открыть страницу `https://www.familysearch.org/`.
2. Открыть инструменты разработчика через **Inspect / Просмотреть код**.
3. Перейти в **Application → Storage → Cookies** (в некоторых версиях сразу **Application → Cookies**).
4. Выбрать домен FamilySearch и найти cookie **`fssessionid`**.
5. Скопировать поле **Value** без кавычек и без Markdown-экранирования. Передать в локальную переменную или приватный файл; не включать в команду, документацию или репозиторий.

Например, создать приватный файл через скрытый ввод Python, без значения в истории команд:

```bash
python3 - <<'PY'
import getpass
import os
from pathlib import Path
path = Path.home() / ".config" / "familysearch" / "session"
path.parent.mkdir(mode=0o700, parents=True, exist_ok=True)
fd = os.open(path, os.O_WRONLY | os.O_CREAT | os.O_TRUNC, 0o600)
os.fchmod(fd, 0o600)
with os.fdopen(fd, "w") as handle:
    handle.write(getpass.getpass("fssessionid: ").strip() + "\n")
PY
python scripts/familysearch_api.py check-session --token-file "$HOME/.config/familysearch/session"
```

`check-session` обращается к официальному endpoint текущего пользователя и сообщает только факт действующей сессии и время проверки; данные профиля не выводятся и не сохраняются. Код 0 означает подтверждённый вход. При отказе прекратить сетевые запросы и проверить вход и скопированное значение. Сессия может истечь или завершиться при выходе из аккаунта; тогда пользователь повторяет получение Value. Нельзя делать вывод о работоспособности всех API или доступности каждой книги только по успешной проверке входа.

В примерах подразумевается настроенный `FS_TOKEN`; при использовании файла добавить `--token-file /private/path/session.txt` к каждой сетевой команде. Справка, локальный поиск и регистрация не требуют сессии. Команды выполнять из папки навыка либо указывать абсолютный путь к скрипту. `<дело>` — существующее дело вне навыка.

## Найти и выбрать книги

```bash
python scripts/familysearch_api.py places "Название села" --out <дело>/sources/fs-places.json
python scripts/familysearch_api.py books --place 1234567 --out <дело>/sources/fs-groups.json
# При известном DGS — вместо поиска по месту:
python scripts/familysearch_api.py books --dgs 007805893 --out <дело>/sources/fs-groups.json
```

`places` возвращает исходные варианты местности в `response`, `--page` выбирает страницу по десять результатов. Проверить историческую юрисдикцию: административный центр и район не взаимозаменяемы.

`books` принимает ровно один из `--place` и `--dgs`, сохраняет ведущие нули DGS, проверяет `totalCount` и фактически полученные уникальные группы. При обрезанной выдаче полный результат не сохраняется: сузить место или набор фильмов. Из найденного выбрать только относящиеся к вопросу части; для поднабора сохранить отдельный groups-файл с соответствующим `total`, исходный список оставить.

## Получить записи с возобновлением

```bash
python scripts/familysearch_api.py harvest <дело>/sources/fs-groups.json --tag parish --dir <дело>/sources/familysearch-api-cache --out <дело>/sources/fs-api-coverage.json
```

Фаза A получает ID записей каждого выбранного кадра. Фаза B получает сами записи, включая индексированных родственников, варианты имён, факты и исходные отношения. `--phase a` и `--phase b` разделяют работу. Полный исходный JSON GEDCOM X сохраняется в `raw` **по умолчанию**, вместе с нормализованными полями и временем получения. `--raw` оставлен как явное указание этого режима; `--no-raw` сохраняет только нормализованные поля и не является полной копией ответа. «Полная запись» здесь — весь ответ индекса, а не расшифровка скана или гарантия полноты исторического документа.

Состояние: `fsk_<tag>_frames.json`, `fsk_<tag>_records.json`, `fsk_<tag>_manifest.json`. Повторить ту же команду для продолжения. Успешные кадры и записи используются повторно, ошибки и недостающие данные запрашиваются заново. Состав и порядок кадров привязаны к метке; для другого набора нужна новая метка. Для браузерных контрольных точек использовать отдельную папку: их схема и локальные ID отличаются от API-кэша.

Запросы последовательные, с паузами. Контрольные точки сохраняются каждые 50 кадров / 100 записей, между фазами и при завершении или ошибке. При аварийном завершении теряются только ответы после последней сохранённой точки. Lock-файл исключает одновременную запись; после аварии проверить указанный PID, прежде чем удалять его. При `401`, `403`, `429`, перенаправлении на вход или CAPTCHA сохранить прогресс и остановить запросы. Не повторять блокировку и не использовать другой маршрут для её обхода.

Отчёт отдельно показывает отсутствующие и неудачные кадры, пустые индексы и недостающие/неудачные записи. Неоднозначный ответ `{}` кадра принимается пустым только после проверки отдельно предоставленной сессии через официальный endpoint текущего пользователя. `phase_complete` относится к выбранной фазе; `complete` — к получению выбранных кадров и записей. Незавершённая загрузка возвращает код 1 и сохраняет частичный результат. Нулевой результат индекса не означает отсутствия людей на изображении.

Кэши читаются в память; полный `raw` увеличивает размер. Большие наборы делить по книгам и меткам. Для старого Node.js manifest с другим fingerprint использовать новую метку. Старые нормализованные кэши можно искать локально; потерянные поля без `raw` не восстанавливаются. `--refresh-empty` перепроверяет ранее пустые кадры.

## Локальный поиск и общие реестры

```bash
python scripts/familysearch.py filter parish --dir <дело>/sources/familysearch-api-cache --groups <дело>/sources/fs-groups.json --surnames 'Иванов(?:а)?(?!\w)' --out <дело>/sources/fs-analysis.json
python scripts/register_search.py --case-dir <дело> --input <дело>/sources/fs-analysis.json --research-goal "Проверить записи о родителях"
python scripts/audit_evidence.py --case-dir <дело>
```

Можно объединить несколько меток и groups-файлов. Проверяются все индексированные лица и формы имени, включая родственников и свидетелей. Даты брака сохраняются также из фактов отношения Couple; пол, родство и события не додумываются. В реестры поступают непроверенные артефакты, а не установленные личности или связи. Оригинал, независимость и принадлежность записи человеку проверять по общему протоколу; индекс и его скан — одна исходная цепочка.

Для точечной проверки доступны `search --apid ID` и `search --surname "Иванов" --given "Пётр" --pages 2`. Поиск по имени ограничен страницами и не заменяет покрытие книги. Фильтр `--place` иногда скрывает записи коллекции с незаполненным местом; проверять фактические поля.

## Проверка совместимости

Внутренние интерфейсы: `/records/images/orchestration/`, `/platform/records/images/<APID>/records`, `/platform/records/records/<RID>?flag=fsh`, `/service/search/hr/v2/personas`. Неоднозначный пустой ответ проверяется через `https://api.familysearch.org/platform/users/current.json`. При изменении схемы остановиться и проверить доступную запись, не угадывать поля.

Офлайн-тесты проверяют пагинацию, две фазы, полный `raw`, продолжение, остановку при отказе, покрытие и перенос в реестры. Они не подтверждают текущий доступ конкретного аккаунта к внутренним API. Без отдельно предоставленной сессии не заявлять живую проверку скриптового маршрута. Проверка через браузер не проверяет API-загрузчик.
