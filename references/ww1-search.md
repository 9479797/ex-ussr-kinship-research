# Первая мировая: поиск документов и сбор по местности

Читайте при поиске в «Памяти героев Великой войны 1914–1918» (GWAR). Помощник `scripts/gwar.py` ищет донесения, госпитальные и наградные записи; карточки использовать для выхода на документ и различения кандидатов по месту рождения, части и событию. Протокол доказательств и реестры остаются общими для дела.

## Выбрать запрос

Начать с различающих признаков человека. Если фамилия искажена или нужно проверить семейный круг, собрать записи по исторической местности. Учитывать омонимы волостей и писарские ошибки: серверный фильтр не гарантирует правильную принадлежность всех результатов.

```bash
python scripts/gwar.py search --surname "Иванов" --given "Пётр" --gubernia "Название губернии" --out <дело>/sources/gwar-person.json
python scripts/gwar.py search --birth-place "Название села" --gubernia "Название губернии" --out <дело>/sources/gwar-village.json
python scripts/gwar.py volost --volost "Название волости" --gubernia "Название губернии" --max-records 5000 --out <дело>/sources/gwar-volost.json
```

Команды — из папки навыка; иначе использовать абсолютный путь к скрипту. `<дело>` хранится вне навыка. Нужен Python 3, стандартная библиотека; аккаунт не требуется, но доступность проверять по ответу сайта. Отсутствие доступа не означает отсутствия человека.

`search` принимает также `--patronymic`, `--event-place`, `--regiment`. `--event-place` относится к месту события, `--birth-place` — к месту рождения. `--gubernia` фильтрует губернию рождения. Не подменять один вид места другим.

По умолчанию проверяются все три вида карточек. `--kind reports hospitals awards` выбирает нужные; можно указать один. Режим `volost` задаёт место рождения и губернию, а не место службы. Подборка не является полной переписью военнослужащих, жителей или семей: один человек может иметь несколько карточек, а многие не представлены вовсе.

## Покрытие и продолжение

`--out` обязателен и одновременно служит контрольной точкой. Файл содержит исходные `hits`, запрос, виды записей, точный счётчик источника, позицию следующей страницы и `coverage`. По умолчанию лимит — 1000 карточек; выбирать объём по вопросу. Если общий счётчик больше лимита, выдача помечается неполной (код выхода 1). Повторить команду с тем же файлом и при необходимости увеличить `--max-records`. Изменение запроса или видов карточек требует другого файла. Результаты сохраняются после каждой страницы и при ошибке; два процесса не могут писать в один файл.

Последовательные страницы содержат не более 1000 записей, с паузами. Повторная/пустая страница до общего счётчика не считается полной выдачей. При изменении счётчика или содержимого карточки проверить выдачу заново в другом файле. При `401`, `403`, `429`, CAPTCHA или блокировке сохранить состояние и прекратить запросы; не обходить защиту и не переносить этот способ на порталы Второй мировой.

## Найти изображение

В карточке искать `documents_pages.pages_id`, затем:

```bash
python scripts/gwar.py page --pages 10063712 10063713 --out <дело>/sources/gwar-pages.json
```

Команда возвращает `image_url`, координаты `zones` и исходное `obraz_s_oblastyami`. Координаты относятся к скану источника; наличие URL не означает, что изображение уже скачано или прочитано. При разрешённом сохранении использовать обычный браузерный маршрут, записать архивный шифр и проверить строку, соседние строки и оборот. Если источник требует контекст страницы, открывать её обычным способом, не подменять средства защиты.

## Записать находки

```bash
python scripts/register_search.py --case-dir <дело> --input <дело>/sources/gwar-person.json --research-goal "Проверить службу и место рождения кандидата"
python scripts/audit_evidence.py --case-dir <дело>
```

Переносятся найденные карточки как `index` / `lead-only`, их исходные поля, ID, локальные снимки с SHA-256 и поиск с покрытием. Число карточек не превращается в число людей; одинаковые ФИО не объединяются. Личности, связи, информанта и независимость устанавливать после чтения документов по шагам 7–10. До оценки `independence_group` пуст; предупреждение аудита сохранять как незавершённую проверку. Подробности повторного импорта — `familysearch-indexes.md`, раздел «Перенос в дело».

Служебный `_score` и порядок сортировки зависят от запроса и не создают новую версию документа. Повтор одной карточки в поиске по фамилии и по местности с теми же исходными полями использует прежний артефакт, сохраняя оба поиска в журнале. Изменение самих исходных полей сохраняется отдельным снимком. Повторное чтение уже полного локального кэша не меняет дату получения карточек.

## Технические сведения

Публичная сессия начинается на `GET /heroes/`, поиск — `POST /gt_data/?builder=Heroes` с полями расширенного поиска сайта; сканы — `builder=HeroesStranitsa` по `linkedPages`. Обе POST-операции только читают источник. Формат ответа проверяется; изменение внутреннего API не исправлять догадками.

Сертификаты Russian Trusted Root/Sub CA из `scripts/ca/` взяты из предоставленного пользователем помощника; исходные точки распространения: `nuc-cdp.digital.gov.ru/cdp/rootca_ssl_rsa2022.crt` и `subca_ssl_rsa2024.crt`. Они подключаются только к HTTPS-клиенту GWAR; системное хранилище доверия не меняется, проверка TLS не отключается, новые сертификаты автоматически не скачиваются. При ошибке цепочки проверить источник и срок сертификатов обычными средствами.

Поисковая часть адаптирована из `russian-archives/scripts/gwar.mjs` и перенесена на Python. Яндекс Архивы, Archive.org и инструменты создания дерева в эту доработку не входят.
