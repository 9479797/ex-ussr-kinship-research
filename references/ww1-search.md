# Первая мировая: поиск документов и сбор по местности

Читайте при поиске в «Памяти героев Великой войны 1914–1918» (GWAR). Помощник `scripts/gwar.py` ищет донесения, госпитальные и наградные записи; карточки использовать для выхода на документ и различения кандидатов по указанной местности, части и событию. Протокол доказательств и реестры остаются общими для дела.

## Выбрать запрос

Начать с различающих признаков человека. Если фамилия искажена или нужно проверить семейный круг, выполнить ограниченный поиск по исторической местности с учётом правил источника. Учитывать омонимы волостей и писарские ошибки: серверный фильтр не гарантирует правильную принадлежность всех результатов.

```bash
python scripts/gwar.py search --surname "Иванов" --given "Пётр" --gubernia "Название губернии" --out <дело>/sources/gwar-person.json
python scripts/gwar.py search --birth-place "Название села" --gubernia "Название губернии" --out <дело>/sources/gwar-village.json
python scripts/gwar.py volost --volost "Название волости" --gubernia "Название губернии" --max-records 5000 --out <дело>/sources/gwar-volost.json
```

Команды — из папки навыка; иначе использовать абсолютный путь к скрипту. `<дело>` хранится вне навыка. Нужен Python 3, стандартная библиотека; аккаунт не требуется, но доступность проверять по ответу сайта. Отсутствие доступа не означает отсутствия человека.

`search` принимает также `--patronymic`, `--event-place`, `--regiment`. `--event-place` относится к месту события. `--birth-place` передаёт `birth_place` (населённый пункт), `--gubernia` — `birth_place_gubernia`, а `volost --volost` — отдельный `birth_place_volost`. Названия API-полей не устанавливают смысл исторической записи: в публичной форме `/heroes/`, проверенной 26.10.2026, эти три поля находятся в группе «Место жительства / место призыва на военную службу». Место рождения устанавливать по самому документу.

По умолчанию проверяются все три вида карточек. `--kind reports hospitals awards` выбирает нужные; можно указать один. Режим `volost` задаёт волость и губернию из указанной группы формы, а не населённый пункт или место службы. Подборка не является полной переписью военнослужащих, жителей или семей: один человек может иметь несколько карточек, а многие не представлены вовсе.

Если фамильный поиск мало различает кандидатов или имя отца могло попасть в поле фамилии, рассмотрите ограниченный поиск по исторической волости и губернии, затем отберите подходящие варианты имени и имени отца (`ex-ussr-locale-guide.md`, раздел 3). Проверяйте полезные варианты написания волости по найденным записям, сохраняя фактическое покрытие и ID карточек. Полная выгрузка волости и перебор всех форм не требуются.

## Покрытие и продолжение

`--out` обязателен и одновременно служит контрольной точкой. Файл содержит исходные `hits`, запрос, виды записей, точный счётчик источника, позицию следующей страницы и `coverage`. По умолчанию лимит — 1000 карточек; выбирать объём по вопросу. Если общий счётчик больше лимита, выдача помечается неполной (код выхода 1). Повторить команду с тем же файлом и при необходимости увеличить `--max-records`. Изменение запроса или видов карточек требует другого файла. Результаты сохраняются после каждой страницы и при ошибке; два процесса не могут писать в один файл.

Последовательные страницы содержат не более 1000 записей, с паузами. Повторная/пустая страница до общего счётчика не считается полной выдачей. При изменении счётчика или содержимого карточки проверить выдачу заново в другом файле. При `401`, `403`, `429`, CAPTCHA или блокировке сохранить состояние и прекратить запросы; не обходить защиту и не переносить этот способ на порталы Второй мировой.

## Сравнить написания местности

Если название села в карточке не опознаётся, сравните его с написаниями в других сохранённых выдачах (по фамилии, по волости, по соседним сёлам). Команда работает только с локальными файлами и к сайту не обращается:

```bash
python scripts/gwar.py places --input <дело>/sources/gwar-person.json <дело>/sources/gwar-volost.json --target "Название как в карточке" --out <дело>/sources/gwar-places.json
```

Карточки группируются по губернии, уезду и волости. Для каждого написания указаны число карточек, их ID и полные ключи (`_index|_type|_id`), различающие одноимённые ID в разных типах записей. Конфликтующие версии одной карточки требуют сравнения исходных файлов; исходная выдача не заменяется выходным файлом. С `--target` написания ранжируются по сходству с неопознанным названием (буквы и согласный остов). Сходство только упорядочивает проверку: оно не устанавливает тождество мест. Строки разбираются по запятым, и тип пункта («с.», «д.», «селение») при сравнении отбрасывается. Если формат поля другой, сверяйте с исходной карточкой. Неполная входная выдача даёт код выхода 1 и `coverage.complete: false`. Метод расшифровки и проверки кандидата — `ex-ussr-locale-guide.md`, раздел 1, «Искажённое или неопознанное название места».

## Найти изображение

В карточке искать `documents_pages.pages_id`, затем:

```bash
python scripts/gwar.py page --pages 10063712 10063713 --out <дело>/sources/gwar-pages.json
```

Команда возвращает `image_url`, координаты `zones` и исходное `obraz_s_oblastyami`. Координаты относятся к скану источника; наличие URL не означает, что изображение уже скачано или прочитано. При разрешённом сохранении использовать обычный браузерный маршрут, записать архивный шифр и проверить строку, соседние строки и оборот. Если источник требует контекст страницы, открывать её обычным способом, не подменять средства защиты.

Проверьте, что по `image_url` получено изображение, а не HTML (`field-lessons.md`, раздел 7, «Проверка полученной копии»). По наблюдению автора [#50](https://github.com/DenisSergeevitch/ex-ussr-kinship-research/pull/50) от 27.10.2026, прямой запрос к нему возвращал страницу защиты с HTTP 503, а тот же образ открывался в просмотрщике сайта `https://gwar.mil.ru/heroes/document/<documents_id>/?page_id=<pages_id>`. Для карточек донесений и госпитальных записей автор сообщил адрес `https://gwar.mil.ru/heroes/<_type><_id>/` (например, `/heroes/chelovek_donesenie<ID>/`); `register_search.py` записывает его в реестр. Адрес вида `/heroes/?ids=<_id>`, по тому же наблюдению, давал пустую выдачу. При проверке сопровождения 27.10.2026 веб-инструмент получил таймаут GWAR; работу этих маршрутов независимо не подтвердили. Сохранённый локатор не доказывает доступность или чтение карточки.

## Военнопленные

Карточки военнопленных РГВИА (на сайте — «Картотека военнопленных», адреса `/heroes/chelovek_plen…/`) составлялись в России по спискам, полученным из Германии и Австро-Венгрии. `scripts/gwar.py` ищет донесения, госпитальные и наградные записи; картотеку пленных проверять через форму сайта.

- **Искажения.** Фамилии и места прошли двойную транслитерацию: немецкое z передаётся как «з» вместо «ц», sch — как «ш», окончания теряются. Сохранять написание карточки и сопоставлять его с вариантами по `ex-ussr-locale-guide.md`.
- **Поля.** Часть, губерния, «род.» (родом из), место и дата пленения, лагерь, номера списков. Номера сохранять: они могут вести к исходному списку. Календарь даты на карточке не указан; расхождение на день со списком потерь полка само по себе не опровергает тождество.
- **Две карточки на одно имя.** Карточку с другим номером полка, без отчества или губернии связывать с человеком только как вероятную: по имени, сходной фамилии, месту и дате пленения, соседним лагерям. Связь карточек, которую показывает сайт, сохранять как наводку.
- **Датский Красный Крест.** Списки русских военнопленных в Германии шли через отдел военнопленных Датского Красного Креста в Копенгагене; в архиве Международного комитета Красного Креста о русских пленных в Германии материалов немного ([справка ICRC](https://grandeguerre.icrc.org/Content/help/FAQ_en.pdf); строка МККК — seed-sources.md, раздел «Военные источники»). Архив отдела хранится в Rigsarkivet: алфавитная картотека русских военнопленных в Германии (1915–1918), списки 1915 года, указатель к спискам (1914–1919) и указатель к переписке о разыскиваемых (1916–1919). Датская запись может передавать место родом так, как его записал немецкий писарь, что помогает разобрать искажённое название на русской карточке. Образов в сети нет; поиск заказывается через форму архива (`correspondence.md`, раздел 1). В заказе указать варианты фамилии в немецкой транскрипции, часть, дату и место пленения, лагерь, номера с русских карточек и лимит часов.

## Записать находки

```bash
python scripts/register_search.py --case-dir <дело> --input <дело>/sources/gwar-person.json --research-goal "Проверить службу и указанную местность кандидата"
python scripts/audit_evidence.py --case-dir <дело>
```

Переносятся найденные карточки как `index` / `lead-only`, их исходные поля, ID, локальные снимки с SHA-256 и поиск с покрытием. Число карточек не превращается в число людей; одинаковые ФИО не объединяются. Личности, связи, информанта и независимость устанавливать после чтения документов по шагам 7–10. До оценки `independence_group` пуст; предупреждение аудита сохранять как незавершённую проверку. Подробности повторного импорта — `familysearch-indexes.md`, раздел «Перенос в дело».

Служебный `_score` и порядок сортировки зависят от запроса и не создают новую версию документа. Повтор одной карточки в поиске по фамилии и по местности с теми же исходными полями использует прежний артефакт, сохраняя оба поиска в журнале. Изменение самих исходных полей сохраняется отдельным снимком. Повторное чтение уже полного локального кэша не меняет дату получения карточек.

## Технические сведения

Публичная сессия начинается на `GET /heroes/`, поиск — `POST /gt_data/?builder=Heroes` с полями расширенного поиска сайта; сканы — `builder=HeroesStranitsa` по `linkedPages`. Обе POST-операции только читают источник. Формат ответа проверяется; изменение внутреннего API не исправлять догадками.

Сертификаты Russian Trusted Root/Sub CA находятся в `scripts/ca/`; точки распространения: `nuc-cdp.digital.gov.ru/cdp/rootca_ssl_rsa2022.crt` и `subca_ssl_rsa2024.crt`. Они подключаются только к HTTPS-клиенту GWAR; системное хранилище доверия не меняется, проверка TLS не отключается, новые сертификаты автоматически не скачиваются. При ошибке цепочки проверить источник и срок сертификатов обычными средствами.

Поисковая часть адаптирована из `russian-archives/scripts/gwar.mjs` и перенесена на Python.
