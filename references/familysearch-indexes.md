# FamilySearch: поиск по готовым индексам

Читайте при поиске в индексированных метрических книгах по месту или известному DGS. Помощник использует готовые структурированные записи, не распознаёт изображения и не работает с деревом. Неиндексированные страницы читать по `field-lessons.md`; оценка найденного остаётся в `evidence-protocol.md`.

## Выбрать объём и доступ

1. Установить историческое место, приход и годы по вопросу. Не выбирать между одноимёнными населёнными пунктами без оснований; при необходимости вести оба варианта отдельно.
2. Найти группы по месту или DGS и проверить названия, годы, конфессию, `frames` и `indexed`. Счётчики описывают метаданные сервиса, а не полноту или точность расшифровки.
3. Получать только относящийся к задаче набор книг. Условия коллекции и возможности аккаунта проверять перед получением; внутренние веб-интерфейсы могут меняться. Возможность HTTP-запроса сама по себе не означает разрешение на выгрузку.
4. Если пользователь уже вошёл во встроенном браузере, использовать эту сессию. Не просить отдельного входа или файла cookie ради локального скрипта. Поиск и чтение индекса вести в браузере; доступные текстовые строки сохранять для локального анализа по разделу ниже.
5. Агент читает кадры последовательно, соблюдая ограничения сайта. При отказе доступа, ограничении запросов, перенаправлении на вход или CAPTCHA остановить этот маршрут, сохранить состояние и продолжить другие источники. Не повторять блокировку автоматически.

Все команды выполняются Python 3 со стандартной библиотекой. Примеры — из папки навыка; при другой рабочей директории указывать абсолютный путь к скрипту. `<дело>` — существующее дело вне навыка; не создавать новое ради FamilySearch.

## Действующая браузерная сессия

Открыть обычный поиск исторических записей в сессии пользователя. Использовать известный фильм через фильтр Image Group Number (DGS) / Film Number, коллекцию, место и годы; прочитать текст индекса в выдаче или просмотрщике. Это готовые индексированные сведения, не OCR скана. При доступном фильтре основного участника учитывать также других лиц записи. Отсутствие фамилии в общей выдаче не закрывает поиск по конкретной книге.

Для выбранного объёма сохранять уже отображённые строки индекса и их устойчивые ссылки. Если инструмент браузера поддерживает чтение DOM, извлекать текст видимых строк и ссылки из DOM; не обращаться к скрытому состоянию приложения, не извлекать cookie и не выдавать непрочитанные страницы за проверенные. Повторять по доступным страницам с паузами, отмечать ограничения выдачи и оставшиеся диапазоны в рабочем плане. Даже полный просмотр выдачи не доказывает полноту индекса книги.

Минимальный JSON-снимок для локального анализа:

```json
{
  "url": "https://www.familysearch.org/en/search/record/results",
  "captured_at": "2026-10-25T12:00:00Z",
  "scope": {"description": "Выбранный DGS и годы; первая страница", "page": 1},
  "rows": [{"url": "https://www.familysearch.org/ark:/61903/1:1:EXAMPLE", "name": "Иван Иванов", "text": "Исходный текст индексированной строки с родственниками", "image_url": ""}]
}
```

Данные и дату брать из фактически выполненного чтения, а не из примера. Передать один или несколько снимков:

```bash
python scripts/familysearch.py browser-import <дело>/sources/fs-page-1.json <дело>/sources/fs-page-2.json --surnames 'Иванов(?:а)?(?!\w)' --out <дело>/sources/fs-analysis.json
```

`browser-import` работает без сети и сессии; ищет по полному тексту наблюдённых строк, включая имена родственников, если они отображены. Без шаблонов сохраняет все переданные строки. Совпадение в тексте не определяет автоматически, кому принадлежит имя: `pid` и `principal` совпадения остаются неизвестными. Даты и роли родителей не извлекаются догадками из строки, исходный текст хранится целиком. Одинаковые снимки записи не дублируются; расходящиеся версии не сливаются молча.

Результат имеет тот же формат `candidates` для переноса в существующие реестры. Его покрытие намеренно ограничено наблюдёнными строками (`complete: false`), а не всеми кадрами фильма. Покрытие выбранной книги учитывает браузерный сбор ниже. Браузерный импорт и ограниченный `search` возвращают 0 при успешной обработке своего объёма, не обещая полного покрытия книги.

### Индекс всей выбранной книги

В панели Names просмотрщика имена могут быть кнопками, без отдельной ARK-ссылки в каждой строке. Не отбрасывать их и не выдумывать `1:1`-идентификаторы. Сохранять устойчивый URL изображения, номер кадра, номер группы записей внутри кадра, исходный текст и отображённые имена с их подписями. Для этого `browser-import` принимает также снимок книги:

```json
{
  "source": "familysearch-browser-book",
  "book": {"dgs": "000000001", "group_id": "EXAMPLE-GROUP", "expected_frames": 2},
  "frames": [
    {"number": 1, "url": "https://www.familysearch.org/ark:/61903/3:1:EXAMPLE-1", "status": "not-indexed", "rows": []},
    {"number": 2, "url": "https://www.familysearch.org/ark:/61903/3:1:EXAMPLE-2", "status": "indexed", "rows": [
      {"entry": 1, "name": "Иван Иванов", "text": "Vital Records | Primary\nИван Иванов\nParent\nПётр Иванов", "people": [
        {"name": "Иван Иванов", "label": "Vital Records | Primary\nИван Иванов"},
        {"name": "Пётр Иванов", "label": "Parent\nПётр Иванов"}
      ]}
    ]}
  ]
}
```

Значения в примере условные. Число кадров и группу брать из интерфейса выбранной части, а не всего DGS: один фильм может содержать несколько книг. У каждого прочитанного кадра сохранять фактический `captured_at`. Переключать кадры штатным полем номера, дожидаться завершения загрузки панели имён, проверять текущий номер, отсутствие skeleton-индикаторов и наличие строк либо явного сообщения «This image has not been indexed». Не полагаться на `networkidle`: фоновые запросы могут не прекращаться. Пустая загружающаяся панель и ошибка «Cannot Display Image» не являются кадром без индекса. Обычный временный сбой можно повторить после паузы; при отказе доступа, CAPTCHA или `429` остановиться по общим правилам.

Сохранять снимки по мере чтения обычными файловыми средствами, отдельно от навыка. После перерыва прочитать контрольную точку и продолжить с отсутствующих кадров. Можно передать несколько снимков той же книги: одинаковые кадры и строки не дублируются, расхождения отклоняются, пропущенные номера строк не позволяют считать кадр завершённым. `status: failed` с пустым `rows` сохраняет неудачную проверку и не даёт полного покрытия.

В этом режиме `coverage.complete` относится **только к проверке состояния индекса всех выбранных кадров**. `not_indexed_frames` остаются непрочитанными по оригиналу; полнота расшифровки не установлена. Для поиска людей на них нужен обычный маршрут чтения сканов. Локальный ID `browser-observation:<group>:<frame>:<entry>` — идентификатор наблюдения, не RID FamilySearch и не личность. Поле `registry` содержит все наблюдённые группы записей, а `candidates` — только совпадения с шаблонами. Если интерфейс явно показывает отдельные имена в `people`, совпадение можно отнести к этому локальному элементу; роль сохраняется как подпись индекса, без автоматического установления родства или пола.

Исходное написание в одном индексе бывает смешанным: кириллица, латинская транслитерация, сокращения. Искать нужные варианты явно; не исправлять их молча. Типы записей в описании книги могут быть неполными — проверять фактические поля найденной записи.

## Сбор индекса через текущую сессию

Поиск местности, выбор книг по месту или DGS и поиск по имени выполнять обычным интерфейсом FamilySearch во встроенном браузере. Проверять историческую юрисдикцию и каждую выбранную часть фильма. Это работа агента: пользователь задаёт исследовательскую цель и при необходимости входит на сайт. Для этого маршрута отдельная авторизация не нужна. Для необязательной загрузки полных индексированных записей отдельным скриптом читать [familysearch-api-harvest.md](familysearch-api-harvest.md); его настройка не требуется для браузерного поиска.

Массовый сбор (`harvest`) — тот же браузерный маршрут, выполненный последовательно для всех кадров выбранной книги. Агент сохраняет метаданные `book` из интерфейса в `<дело>/sources/fs-book.json`, затем сам запускает:

```bash
python scripts/familysearch.py harvest <дело>/sources/fs-book.json --tag parish --dir <дело>/sources/familysearch-cache --out <дело>/sources/fs-progress.json
```

Файл книги содержит `{"book": {"dgs": "000000001", "group_id": "EXAMPLE-GROUP", "expected_frames": 2}}` с фактическими значениями выбранной части. Команда создаёт контрольную точку `fsk_parish_browser.json` и возвращает `pending_frames` и следующую порцию `next_frames`. Она работает локально; браузером управляет агент имеющимися инструментами. Не выдавать запуск команды за получение индекса.

Для повторяющихся действий использовать [процедуру браузерного сбора](familysearch-browser-harvest.md). Прочитать следующую порцию через текущую сессию, сохранить фактический снимок кадров в JSON обычным файловым инструментом и принять его в контрольную точку:

```bash
python scripts/familysearch.py harvest <дело>/sources/fs-book.json --tag parish --dir <дело>/sources/familysearch-cache --batch <дело>/sources/fs-batch-01.json --out <дело>/sources/fs-progress.json
```

Продолжать самостоятельно с `next_frames`, пока `coverage.complete` не станет истинным или не возникнет конкретная блокировка доступа. После перерыва повторить команду без `--batch`: сохранённые кадры повторно не читаются, неудачные остаются в очереди. Успешный код выхода означает принятую контрольную точку, а не завершение всей книги. Противоречащий снимок уже сохранённого кадра требует отдельной версии; не затирать его. Сохранение атомарное, конкурентная запись блокируется.

## Искать локально и проверять кандидатов

```bash
python scripts/familysearch.py browser-import <дело>/sources/familysearch-cache/fsk_parish_browser.json --surnames 'Иванов(?:а)?(?!\w)' --beacons 'П[её]тр\s+Иванович' --out <дело>/sources/fs-analysis.json
```

Поиск проверяет весь сохранённый текст и все явно показанные имена, включая родственников и свидетелей. Выражения — Python `re`; варианты кириллицы и латиницы задавать явно. Можно передать `--config` с `{"surnames": {"Ивановы": "Иванов"}, "beacons": {}}`. Совпадение у супруга не превращать в фамилию основного участника.

Найденные записи открывать через кнопку имени или доступную ARK-ссылку в той же браузерной сессии. Сохранять фактические поля, даты, роли, цитату, URL и время наблюдения. Кнопка может открывать панель редактирования: её только читать, не менять данные. Сбор панели Names не считать получением полного GEDCOM X или всех полей карточки. Если нужны подробности каждой записи, прочитать карточки всего выбранного набора тем же способом и отдельно учитывать непрочитанные; не подменять эту работу краткими подписями имён.

Для ранее сохранённых кэшей исходного Node.js-помощника остаётся локальный `filter`:

```bash
python scripts/familysearch.py filter parish --dir <дело>/sources/old-cache --groups <дело>/sources/fs-groups.json --surnames 'Иванов' --out <дело>/sources/fs-analysis.json
```

Он не обращается к FamilySearch. Совместимость кэшей не требует сохранять прежний способ авторизации. Поля, отсутствующие в старом файле, не восстанавливать догадками. Файлы читаются в память; большие наборы делить по книгам. Отсутствие совпадения относится только к прочитанному объёму индекса; неиндексированные кадры требуют чтения изображений.

Локальный `filter` отдельно показывает `retrieval_complete` (получены все переданные кадры и записи) и `frame_lists_complete` (число уникальных ID соответствует известному размеру каждой книги). Неизвестный `frames`, расхождение счётчиков или повторные ID дают `complete: false` и код выхода 1, сохраняя доступные находки. Подробности — в `frame_list_coverage`; неполный список не превращается в отрицательный результат поиска. Для старых неоднозначных пустых ответов `{}` без `session_checked_at` нужна перепроверка через API-помощник в фазе A.

## Перенос в дело

```bash
python scripts/register_search.py --case-dir <дело> --input <дело>/sources/fs-analysis.json --research-goal "Найти записи о родителях основного человека"
python scripts/audit_evidence.py --case-dir <дело>
```

Из `filter` переносятся только записи с совпадениями, из `search` — полученные записи, из `browser-import` — наблюдённые строки, прошедшие выбранные шаблоны. Скрипт сохраняет снимки JSON с SHA-256 в `sources/`, добавляет непроверенные артефакты в `artifact-register.csv` и выполненный поиск с покрытием в `search-log.csv`. Повторный перенос того же снимка не создаёт дубликаты и не изменяет ручную оценку. Новый снимок изменившейся записи сохраняется отдельно. Сбой между записью двух CSV исправляется повтором той же команды.

`person-register.csv`, утверждения и родственные связи не заполняются автоматически. Проверить кандидатов по оригиналам, назначить независимость, затем продолжить шаги 7–10. Незавершённая оценка независимости вызывает предупреждение существующего аудита; не устранять его выдуманной группой. При добавлении скана использовать ту же группу исходного документа, что и у его индекса. Пустая выдача означает только отсутствие совпадений в указанном объёме.

## Сопровождение

Способ использования исходного навыка сохраняется: агент исследует через доступный браузер, локальные Python-помощники сохраняют и анализируют результаты. Не извлекать браузерную сессию во внешний HTTP-клиент и не требовать экспорт cookie для обычного поиска. Необязательный API-помощник использует только отдельно предоставленную сессию по `familysearch-api-harvest.md`. Изменение интерфейса проверять по текущему DOM; сохранённый селектор не считать гарантией доступности.

Полный скриптовый цикл доступен отдельно в `familysearch_api.py`, а браузерный способ работы сохраняется. Функции дерева и эвристическое установление родства исключены. Частные результаты исследований и сессии не включать в навык или тесты.
