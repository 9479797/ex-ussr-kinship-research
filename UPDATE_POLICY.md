# Политика обновлений и уведомлений

Этот форк содержит методику ex-USSR Kinship Research и собственные исторические дополнения. **Обновление стороннего оригинала и синхронизация своей версии на Mac — разные процессы.**

## 1. Проверка оригинала

- Источник: https://github.com/DenisSergeevitch/ex-ussr-kinship-research
- Автоматизация: [check-upstream.yml](.github/workflows/check-upstream.yml).
- Еженедельно (понедельник, 10:27 UTC) и при ручном запуске GitHub Actions проверяет коммиты оригинала, ещё не включённые в `main` этого форка.
- Если обновление есть, workflow открывает **один GitHub Issue для конкретной новой вершины upstream**, отмечает `@9479797` и назначает задачу владельцу. Повторных Issue для того же SHA нет (в пределах проверяемой истории Issue).
- Важное условие: для этого репозитория должен быть **включён GitHub Issues** в Settings → General → Features → Issues; сейчас раздел Issues требует включения вручную. Также должны работать GitHub Actions и уведомления аккаунта.
- В GitHub Settings → Notifications необходимо разрешить уведомления о назначениях или упоминаниях; настроить электронную почту/мобильные push при необходимости.

**Никаких автоматических слияний upstream.** Перед обновлением сравнивать изменения, сохранять 10 исторических дополнений и исключения `.gitignore`, исключать личные семейные данные, при необходимости создавать контрольную ветку. Только после проверки обновлять `main` своего форка.

## 2. Автоматическая синхронизация Mac

После принятия и публикации изменений в **своём** GitHub можно обновлять локальную копию автоматически. Общий синхронизатор расположен в [historian-research/scripts/sync-macos.sh](https://github.com/9479797/historian-research/blob/main/scripts/sync-macos.sh) и устанавливается через [install-macos-sync.sh](https://github.com/9479797/historian-research/blob/main/scripts/install-macos-sync.sh).

Он работает ежедневно через пользовательский macOS `launchd`, только с двумя известными репозиториями, только с `main`, проверяя `origin`, чистоту рабочей папки и возможность `fast-forward`. При локальных изменениях, расхождении веток или неподтверждённом адресе GitHub **не обновляет** репозиторий и пишет причину в журнал. `reset --hard`, `force pull` и изменение семейного дела не выполняются.

**Запуск локальной автоматизации требует однократного действия на Mac.** Файлы из GitHub самостоятельно не устанавливают задания `launchd`.

## 3. Ограничения

- Github Actions в публичных репозиториях может отключить запланированные проверки после 60 дней без активности; периодически проверять раздел Actions и при необходимости включать workflow вручную.
- Проверки не выполняют автономный исторический анализ и не подтверждают качество новых версий — они только обнаруживают обновления.
- Получение обновлений Mac не означает, что Claude Code или другой агент автоматически начал использовать новые файлы из `~/.claude/skills/`. Возможные отдельные установки нужно проверять индивидуально.
